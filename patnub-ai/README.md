# patnub.ai (Android)

Native Android app for the Alaga Health build plan
([`../ALAGA_HEALTH_ITERATIVE_BUILD_PHASES.md`](../ALAGA_HEALTH_ITERATIVE_BUILD_PHASES.md)).
It is separate from the web mockup in `../alaga-health/`. The on-device LLM runtime lives in
the `../msr_engine/` submodule.

## Build

Open this folder (`patnub-ai/`) in Android Studio and let it sync, or from a terminal:

```sh
./gradlew :app:assembleDebug        # APK in app/build/outputs/apk/debug/
./gradlew :app:installDebug         # install on a connected phone
```

Requires JDK 17+ (Android Studio's bundled JDK works) and Android SDK platform 37.

## Layout

```
app/src/main/java/ai/patnub/
  MainActivity.kt              entry point, edge-to-edge, sets the Compose theme
  PatnubApplication.kt         owns the database and engine instances, seeds demo users, loads the engine
  engine/Engine.kt             Kotlin interface mirroring the libmsr_engine C API
  engine/FakeEngine.kt         simulated engine for emulators and UI work without the model
  data/local/PatnubDatabase.kt Room database (patnub_local.db), 8 tables
  data/local/entity/           one entity per table, plus shared enums
  data/local/dao/              type-safe queries (DAOs)
  data/local/Converters.kt     Instant, LocalDate and JSON list column conversions
  data/local/SeedData.kt       demo knowledge passages (placeholders, not real DOH/WHO/PNF text)
  identity/PatientIdentity.kt  the phone owner's profile and X25519 key pair (private key wrapped by Android Keystore)
  ui/onboarding/               first-launch profile form
  transfer/                    check-in code, record QR opener (RecordCodec), importer, trust root;
                               all checked against ../contract/vectors.json
  assistant/                   red-flag gate, dose-change guard, keyword retrieval, prompt builder, Assistant pipeline
  ui/patient/                  Assistant chat, Records timeline, Scan (check-in code + record scan, preview, consent)
  ui/components/QrScanner.kt   CameraX + ML Kit (bundled model, offline)
  ui/components/QrCode.kt      QR rendering (ZXing core)
  ui/PatnubApp.kt              root Scaffold: top bar with engine status pill, bottom tabs (patient-only app; clinicians use ../doctor-web/)
  ui/patient/PatientScreens.kt the 5 Patient tabs (Assistant, Records, Scan, Medicines, Visits)
  ui/components/               shared composables
  ui/theme/                    colors and Material 3 theme
app/src/main/res/              strings, vector icons, adaptive launcher icon, backup rules
app/schemas/                   Room schema JSON, generated by the build (commit it)
```

## Database

Tables and columns match the build plan's Phase 1 schema, so its SQL examples work as written:
`users`, `general_knowledge_chunks` (Collection A), `clinical_records` (Collection B),
`qr_grants`, `patient_consents`, `medication_references`, `visit_items`, `audit_events`.

- Enums are stored as their names (TEXT), timestamps as epoch milliseconds, dates as
  ISO-8601 text, and `*_json` columns as JSON arrays.
- Foreign keys tie records, grants, consents and visit items to `users`. Room turns on
  `PRAGMA foreign_keys` itself. `audit_events` has no foreign keys so the log outlives what it mentions.
- Schema changes need a version bump and a migration. Each build writes the schema JSON
  for the current version under `app/schemas/`.

## Engine

`Engine` mirrors the `libmsr_engine` C API
(`../msr_engine/native/include/msr/engine/engine.h`): load, streamed generate, cancel,
stats and close. Validation, error codes and stats semantics follow `engine.cpp`.

The app currently uses `FakeEngine`, because the JNI bridge to `libmsr_engine` isn't built
yet. `FakeEngine` never reads a model file. It streams placeholder text at the measured
3.00 tok/s and reports the measured 1 GiB numbers as stats. `Engine.isSimulated` is true for
it, and the UI must say so wherever it shows engine output or stats. Keep it for emulators
and for UI work on phones without the 2.3 GiB model.

To switch to the real engine, add a JNI-backed `Engine` implementation and change the one
line in `PatnubApplication` that creates `FakeEngine`.

## Current state

Patient-only app (spec v1.2):

- **Onboarding** creates the phone owner's profile and X25519 key pair.
- **Scan** shows the check-in code for the clinic, and scans record QR codes from the clinic app.
  The phone verifies root → license → staff → record, decrypts, shows a preview, and saves only
  after the patient agrees. Corrected versions replace older ones.
- **Records** lists saved clinician-approved records.
- **Assistant**: emergency red flags short-circuit before any model call; dose-change questions
  are referred to the prescriber; otherwise it retrieves reviewed passages and the patient's own
  consented records and streams an answer (SIMULATED while `FakeEngine` is in use), or falls
  back to the retrieved text when the model is not running.
- Medicines and Visits are still placeholders (Phase 5).

Build note: `/mnt/DEV` was full during development, so builds were run with
`./gradlew -I ~/.cache/patnub-build/tmpbuild.gradle ...` to put outputs under `~/.cache`.

## Privacy defaults

- No `INTERNET` permission. The app is meant to run fully offline. The manifest strips
  network permissions that libraries (ML Kit) would otherwise merge in. Only `CAMERA` is requested.
- `allowBackup="false"` plus `data_extraction_rules.xml` keep app data out of cloud
  backups and device-to-device transfers, since the app will store patient records.
